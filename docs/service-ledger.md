# PrepVault service ledger

Reviewed against the implementation on 2026-10-28. This ledger describes the current local source; it does not establish that every connected service has been exercised with production credentials. No new paid provider account, API subscription or commercial service guarantee is implied.

| --- | --- | --- |
| Calendar | Dates derived locally from recorded inventory/farming fields, plus manual dated tasks. No push notifications, email, scheduled jobs or background reminders. |

Climate labels are not location-specific planting advice. |

| Official weather warnings | Selected coordinates go to ECCC GeoMet weather-alert features for Canada or the US NWS active-alert API. | Automatic coverage is Canada and the US only. Weather warnings do not cover all evacuation, police, drinking-water or utility notices. Official radar opens externally. |

## Provider terms and operational boundaries

- **Open-Meteo / GeoNames:** The implemented keyless endpoint is intended here for personal, noncommercial use. Open-Meteo's free-service terms restrict commercial use and impose request limits; the free endpoint is not an entitlement to unlimited production traffic. A commercial rollout or higher-volume deployment needs an appropriate provider arrangement. Source attribution remains visible. See [Open-Meteo terms](https://open-meteo.com/en/terms) and [geocoding API documentation](https://open-meteo.com/en/docs/geocoding-api).
- **FOSSGIS / Valhalla:** The current integration uses a public, volunteer-operated service without a purchased subscription or uptime commitment. Keep the OpenStreetMap/FOSSGIS attribution and map-correction link. The app serializes uncached calculations with a 1.1-second gap, allows up to 60 per owner per UTC day per server process, and briefly caches matching results per owner. Those in-memory controls are not a global quota across serverless instances; they are appropriate to the limited personal setup, not a high-volume public launch. Review the operator's current usage conditions before scaling. See [OSM Deutschland services](https://www.openstreetmap.de/nutzen/dienste-osm-de/) and [Valhalla service](https://valhalla.openstreetmap.de/directions).
- **ECCC and NWS:** These are the sources of the displayed official weather notices; PrepVault does not issue warnings. The selected point and country determine coverage. Use the linked official notice for current instructions. See [ECCC GeoMet API](https://api.weather.gc.ca/) and [NWS API documentation](https://www.weather.gov/documentation/services-web-api).
- **Open Food Facts:** This is a public food database, not a universal retail catalog. Fields may be incomplete or wrong. The client has an eight-second timeout and a conservative 12 uncached lookups/minute limit, with manual entry on errors or misses. Package size is not silently converted into inventory units, and per-100g nutrition is not treated as package nutrition. See [API documentation](https://openfoodfacts.github.io/openfoodfacts-server/api/) and [barcode entry details](barcode-scanning.md).
- **Radio Browser / broadcasters:** The directory uses public metadata; the broadcaster controls the stream and can remove, restrict or change it. Playing a stream discloses the listener's connection to that broadcaster. Country/state filters do not locate physical transmitters or enumerate emergency radio channels. See [Radio Browser API](https://docs.radio-browser.info/).
- **EchoLink:** This is a separate external service with its own account and operating requirements. PrepVault does not collect its credentials, validate amateur callsigns or control its transmissions. See [EchoLink Web FAQ](https://secure.echolink.org/faq_webapp.htm).

Route times describe modeled movement. Breaks and travel hours are added locally. Daily stopping points are interpolated along the saved geometry and are not verified campsites, lodging, water sources or land-access permission. Selected avoidance circles do not automatically avoid all population centres, use population-density data or identify the least populated route. No map result establishes that a road is open or safe during an emergency.

The Local app blocks third-party requests from the app. Search, forecasts, warning refreshes, public product lookup, radio streams and new routes need the hosted online site. Deliberately opened external guide/EchoLink/radar links can use the internet in their own tab. A downloaded Local app ZIP contains app code and reference PDFs, not the household's plan; import a separate complete backup to transfer personal data.

## Data ownership and backup audit

| Key | Contents | Account switch / complete backup |
| --- | --- | --- |
| `prepvault-calendar` | Manual tasks, done state and reviewed derived-event identifiers | Explicitly allowlisted, validated and restored with the current workspace |
| `prepvault-location` | Selected planning place, country, coordinates and timezone | Explicitly allowlisted, validated and restored with the current workspace |
| `prepvault-offline-routes` | Saved calculated routes and daily travel preferences | Explicitly allowlisted, validated and restored with the current workspace |
| `prepvault-radio-location` | Country and optional region for station discovery | Existing account-scoped setting; can default from the planning location |
| Inventory item barcode | Code on the item and its field record | Part of the existing household inventory snapshot; no separate private lookup cache |

`account-workspace.js` captures only explicit setting keys, stores the departing account's latest settings and clears/replaces active keys for the next account or guest. `backup-storage.js` validates the complete snapshot before a preflighted write, clears settings omitted by a full/legacy restore and preserves settings during a core-only cloud refresh. The view subtree is keyed by `restoreVersion`, so changing/restoring a plan recreates Calendar, Location and Offline maps with the replacement settings. The account-owner storage event reloads other open tabs after an account switch.

The account cache and active browser storage are not encrypted and are not a security boundary against someone with device/browser-storage access. Complete encrypted backups protect exported files. New settings remain local rather than being added to legacy Supabase core sync. Live location-sharing positions, forecast responses, current radio audio, authentication/session material and handbook cache files are not new backup contents. Browser storage can fill or be cleared; saved route geometry can be large, and failed saves must remain visible to the user.

## Reference pictures

Task diagrams are original local SVGs bundled as data with the app. They include alt descriptions and captions, can be enlarged and downloaded, and require no image-service requests. Farm exports embed each picture; original PDFs keep their existing images and byte hashes. Audited PDF-page shortcuts use file page numbers, not printed chapter labels. No professional clinical PDF is linked as a beginner skill visual.

Equipment Manuals remain filename-only references: general diagrams do not establish that an exact manufacturer manual or service procedure has been reviewed. That distinction is displayed on each expanded record.


### Emergency mode

The validated `emergencyPlan` field is part of the working plan, account-isolated snapshots and encrypted backups. Its durable active state changes Overview, the app-wide indicator and mobile shortcuts. Food/water planning is scoped to a chosen property and marked dependants. Three meals, one water allocation and two check-ins are generated in local time for a bounded 1–90 day horizon. Calendar, Rationing and the emergency workspace share completion records. Current targets, property, coverage and today's schedule are included in the adviser's existing bounded allowlist.

Completion does not mutate quantities or send messages. No hardware or background reminders are activated. Existing calorie targets carry forward; water allocations are not drinking limits. Emergency eligibility excludes past/invalid expiry dates and food entries representing livestock/hunting equipment. Normal recorded-inventory totals may include these entries. Plans run locally after restoring a backup in the downloaded app; they are not automatically replicated by legacy core-data sync.
